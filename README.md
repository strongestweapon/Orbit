# Orbit

원형 LED 설치물을 위한 macOS 네이티브 영상 앱입니다. SwiftUI와 Metal로 실시간 영상을 생성하고 OSC 센서 값을 씬 파라미터에 연결합니다.

## 기능

- 코드로 생성하는 8개 아트 씬과 LED 테스트 패턴 12종
- 재생·일시정지·속도·밝기·재생 시간 표시
- 영상 위에 미리보기 FPS / 출력 FPS 표시: GPU 렌더 완료 기준, 약 1초 구간 평균, 0.5초마다 갱신
- 원형 미리보기, 펼친 영상, 4K 출력 배치 동시 표시
- OSC UDP 주소로 파라미터와 이벤트를 직접 제어
- 파라미터 옆 연결 버튼: OSC 수신 주소와 출력을 각각 설정
- 파라미터별 OSC 송신 켜기·끄기, 연속값/트리거 출력 선택과 1회 송신 테스트
- 메인 화면 하단 한 줄: OSC 수신·제어 송신 상태와 최근 주소·값. 네트워크 설정은 OSC 매핑 화면에 통합
- 출력 디스플레이 선택과 실제 출력 프레임에 연동된 빨간 테두리
- 16:9 출력 크기 선택: 화면에 맞춤, HD, FHD, QHD, 4K, 직접 입력
- 외부 모니터 없이 별도 출력 창 사용 및 전체화면 전환
- 공통 조절·매핑·출력 설정 팝업
- 비교용 원본 영상 및 추출 띠 텍스처 재생

기본 영상 소스인 **실시간 생성**은 이미지/영상 텍스처 없이 씬별 코드로 계산합니다. **원본 재생**을 선택하면 번들에 포함된 추출 리소스를 사용합니다. 제어 출력은 OSC Float만 사용하며, Live의 Max for Live 등 OSC 수신 장치에 연결합니다. GitHub의 서명된 업데이트 목록을 실행할 때마다 확인하고, 0.7.1부터 사용자가 설치를 승인한 뒤 업데이트합니다.

## 업데이트 확인과 사용자 승인 (0.7.1)

Sparkle 2.10.1을 사용합니다. 실행 시 자동 확인하고, 새 버전이 있으면 팝업에서 **업데이트 설치 / 나중에**를 선택합니다. 다운로드 후에도 **설치 & 재실행**을 직접 눌러야 재시작합니다. `SUAllowsAutomaticUpdates=false`로 기존 사용자가 저장한 자동 설치 설정까지 차단합니다. 새 업데이트가 없거나 네트워크/서명 검증에 실패해도 기존 앱은 계속 작동합니다. 앱 메뉴의 **업데이트 확인…**과 하단 업데이트 메뉴에서 상태와 마지막 확인 시각을 볼 수 있습니다.

- 영상 출력 창이 열려 있거나 OSC 제어 송신 또는 GPU 성능 측정 중이면 설치·재시작을 보류합니다. 작업이 끝나도 자동 진행하지 않으며, 하단 메뉴의 설치 항목에서 **지금 업데이트 / 나중에**를 다시 선택합니다.
- 자동 확인에서 발견한 새 버전은 운영 작업 중에는 상태만 표시하고, 작업이 끝나면 선택 팝업을 엽니다. 팝업 표시 자체는 다운로드나 재시작을 실행하지 않습니다.
- 배포 목록의 `sparkle:minimumAutoupdateVersion`은 15입니다. 이전 0.6.0·0.7.0의 자동 다운로드 경로도 이번 패치를 사용자 확인 대상으로 처리합니다. 앱의 `OrbitMinimumAutoupdateVersion` 값을 배포 도구가 서명된 목록에 반영합니다.
- 재시작 직전에 씬 조절값과 센서·출력 매핑을 저장합니다. 설정은 앱 외부의 기존 사용자 설정 영역에 보존됩니다.
- 다운로드 전 업데이트 목록의 Ed25519 서명, 압축 해제 전 업데이트 파일의 서명을 검증합니다. 배포 앱은 SUPERLESS Developer ID로 서명합니다.
- 업데이트 목록은 `updates/appcast.xml`, 실행 파일은 GitHub Releases에 둡니다. 아직 공증한 정식 릴리스가 없으면 목록은 비어 있습니다. 공증 전 TEST 패키지는 정식 업데이트로 배포하지 않습니다.
- GitHub 릴리스에는 설명 본문과 DMG·ReleaseNotes.txt 두 첨부만 공개합니다. 수동 설치와 자동 업데이트가 같은 DMG를 사용합니다. 서명된 목록은 저장소에서 제공하고, 체크섬·배포 기록은 로컬에 보관합니다.
- 0.5.4 이하에는 업데이트 기능이 없으므로 0.6.0 이상을 한 번 수동 설치해야 합니다. DMG 안에서 직접 실행하지 말고 Applications에 복사하세요.

### 다음 버전 배포

최초 한 번, 공증에 사용하는 Apple 계정의 **앱 전용 암호**를 Mac 키체인에 등록합니다. 아래 명령은 암호를 화면에 표시하지 않는 입력 창으로 받습니다. Apple 계정의 일반 로그인 암호가 아니라 앱 전용 암호를 입력하세요. 암호를 코드·명령 인자·GitHub에 기록하지 않습니다.

```sh
xcrun notarytool store-credentials OrbitNotary --apple-id super@superless.ai --team-id M38GX6QKSQ
```

`OrbitNotary`를 등록한 뒤에는 DMG 공증에 이 인증을 자동으로 사용합니다. 등록 여부는 `xcrun notarytool history --keychain-profile OrbitNotary`로 확인할 수 있습니다. 인증이 취소되거나 Apple 계정 암호 변경으로 앱 전용 암호가 무효화되면 다시 등록해야 합니다.

`OrbitApp/project.yml`의 버전과 빌드 번호를 증가시키고 `updates/<버전>.txt`에 릴리스 노트를 작성합니다. 아래 경로의 버전은 실제 버전에 맞춥니다. `build` 후 생성된 프로젝트 변경까지 검증하고 커밋·푸시한 뒤 패키징합니다.

```sh
python3 OrbitApp/Tools/release.py build
python3 OrbitApp/Tools/release.py notarize --archive .build/release-0.6.0/Orbit.xcarchive
python3 OrbitApp/Tools/release.py package --app .build/release-0.6.0/notarized/Orbit.app
python3 OrbitApp/Tools/release.py publish Releases/0.6.0
```

`notarize`는 Xcode에 로그인된 유효한 SUPERLESS 개발자 계정으로 앱을 Apple에 제출합니다. `package`는 공증된 앱으로 DMG를 만든 뒤, 키체인의 인증으로 **DMG 자체도 공증**하고 티켓을 부착합니다. 앱 공증만으로는 DMG 공증이 완료되지 않습니다. DMG 공증·실행 허용 검증을 통과한 뒤 이 DMG를 가리키는 업데이트 목록과 체크섬을 생성합니다. 다른 키체인 프로필을 쓰려면 `package --notary-profile <이름>`을 지정하세요.

`publish`는 파일 해시와 DMG 공증을 다시 확인하고 릴리스 파일을 올린 다음 서명된 목록을 갱신·푸시합니다. 패키징 시 기록한 소스 커밋이 현재 커밋 또는 GitHub main과 다르면 게시하지 않습니다. 빌드 후 앱 소스가 바뀌었다면 먼저 다시 빌드해야 합니다.

공증 전 내부 테스트만 하려면 `package --app <서명된 앱 경로> --allow-unnotarized`를 사용합니다. 파일과 폴더에 `TEST`가 표시되며 `publish`는 이를 거부합니다. TEST 패키지 안의 appcast는 시험용으로만 보관하고 `updates/appcast.xml`에 복사하지 마세요.

GitHub 릴리스 초안을 미리 만들어도 됩니다. `publish`는 기존 초안을 이어 사용하고, 검증된 파일을 모두 업로드한 뒤 공개합니다. 이미 공개된 같은 버전은 덮어쓰지 않습니다.

업데이트 비밀키는 Mac 키체인의 Sparkle 계정 `studio.superless.Orbit`에 보관합니다. 저장소에는 공개키만 포함됩니다. 다른 빌드 Mac을 사용할 때는 기존 비밀키를 안전하게 이전해야 하며, 새 키를 임의로 생성해 교체하면 이미 설치된 앱이 다음 업데이트를 검증할 수 없습니다.

목록·DMG 서명 검증은 `OrbitApp/Tools/verify_update.swift`에서 공개키만 사용합니다. 서명을 새로 생성할 때만 비밀키가 필요하며, 검증 단계는 키체인 접근을 요청하지 않습니다.

설치 보류 검증:

```sh
xcrun swiftc OrbitApp/Sources/UpdateInstallationGate.swift OrbitApp/Tests/UpdateInstallationChecks.swift -o /tmp/orbit-update-checks
/tmp/orbit-update-checks
```

`OrbitApp/Tools/test_updater.py`는 별도 번들 ID와 로컬 서버로 변조 목록 거부, ‘나중에’ 이후 실행 유지, 명시적인 설치·재실행 후 build 14 → 15 교체를 시험합니다. `--work`로 독립 폴더, `--initial-mode valid`로 정상 목록부터 시작할 수 있습니다. `UpdatePolicyChecks.swift`는 같은 테스트 번들로 기존 자동 설치 설정이 무시되는지 검증합니다. 실제 Orbit 사용자 설정과 설치 앱은 변경하지 않습니다.

## 실행

macOS 14 이상을 대상으로 합니다. 저장소에 Xcode 프로젝트와 필수 미디어 리소스가 포함되어 있습니다.

일상 실행과 Spotlight 검색용 앱의 설치 경로는 `/Applications/Orbit.app`입니다. 개발 빌드를 사용자에게 적용할 때도 검증한 앱을 이 경로에 설치하고 여기서 실행합니다. `.build`나 Xcode DerivedData에서 실행한 앱은 별도 복사본이므로, 빌드만으로 설치된 앱이 갱신되지는 않습니다. 설치 교체 전 기존 Orbit을 정상 종료해 설정을 저장하고, 복사 후 코드 서명과 실행 파일 일치를 확인합니다.

1. `OrbitApp/Orbit.xcodeproj`를 Xcode에서 엽니다.
2. `Orbit` scheme과 `My Mac`을 선택합니다.
3. Run으로 실행합니다. Space로 재생/일시정지를 전환합니다.

터미널 빌드:

```sh
xcodebuild -project OrbitApp/Orbit.xcodeproj -scheme Orbit \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath .build build
```

Metal 소스는 앱에서 런타임에 컴파일합니다. 별도 Metal Toolchain 다운로드는 이 프로젝트 빌드에 필요하지 않습니다. 프로젝트 설정의 원본은 `OrbitApp/project.yml`이며, 재생성할 때는 XcodeGen으로 `xcodegen generate --spec OrbitApp/project.yml`을 실행합니다.

## 로고

앱 아이콘은 승인된 01번 Light Orbit 디자인입니다. 원본은 `Branding/orbit-icon-master.png`, 생성 프롬프트와 폰트 정보는 `Branding/brand.json`에 있습니다. 시안의 ORBIT 글자는 생성된 레터링이며 특정 폰트를 사용한 결과가 아닙니다. 앱 헤더는 유사한 기하학적 산세리프인 macOS 기본 **Avenir Next Medium**, 17 pt, 자간 4 pt를 사용합니다.

`python3 OrbitApp/Tools/package_icon.py`로 원본의 투명도를 유지하면서 16–1024 px 아이콘을 `OrbitApp/Resources/OrbitAppIcon.icns`로 패키징하고 헤더용 `OrbitLogo.png`를 만듭니다. Finder·Dock·앱 정보 창은 같은 아이콘을 사용합니다.

## 입력·출력 목록 (0.5.0)

0.5.2부터 링 미리보기와 별도 출력 창의 FPS를 각각 표시합니다. 출력이 꺼져 있거나 아직 측정 중이면 `—`, 렌더 완료 프레임이 1초 이상 끊기면 `0.0`입니다. 출력 세션을 새로 시작하면 이전 수치를 지웁니다. 영상 일시정지 중에도 같은 화면을 계속 표시하므로 FPS는 유지될 수 있습니다. 숫자는 각 화면의 GPU 렌더 완료 프레임 기준이며 모니터·LED의 실제 수신·표시 주사율은 아닙니다. 성공한 Metal 작업의 GPU 완료 시각을 사용하며, 완료 시각이 없는 환경에서는 완료 콜백 시각을 사용합니다. 화면 표시 시각이 0으로 반환되는 환경에서도 측정할 수 있고, 화면이 가려졌을 때의 합성기 프레임 생략은 이 수치에 포함되지 않을 수 있습니다.

0.5.3에서는 재생 시간과 FPS를 별도 관찰 객체로 분리했습니다. 숫자가 바뀌어도 센서 목록·슬라이더·전체 미리보기 배치를 다시 계산하지 않고 작은 표시 영역만 갱신합니다. 기본 Xcode `Orbit` Run은 최적화된 `Release` 구성을 사용하며 디버거·GPU 캡처·Metal 검증을 끕니다. 디버깅이 필요하면 Edit Scheme → Run에서 `Debug` 구성과 Debug executable을 선택하고 필요한 검증을 켤 수 있습니다. 성능을 비교할 때는 같은 씬·출력 크기·창 상태와 Release 구성을 사용하세요. 창 전환·최소화 중의 일시적인 값은 지속 재생 성능과 구분해야 합니다.

0.5.4의 FPS 옆 속도계 버튼에서 재생 제한과 최대 성능을 확인할 수 있습니다. 기본 재생은 60 FPS 목표이며 `화면 최대`는 각 창이 위치한 모니터의 최대 주사율을 요청합니다. 창을 다른 모니터로 이동하면 해당 화면에 맞춰 갱신됩니다. 실제 FPS는 처리 부하와 화면 주사율에 따라 달라지며 영상의 시간 진행 속도는 바뀌지 않습니다. 선택한 FPS 설정은 재실행해도 유지됩니다.

`최대 성능 측정 → 5초 측정`은 현재 실시간 씬과 파라미터를 복사해 FHD/QHD/4K 출력을 화면 밖의 GPU 텍스처에 제한 없이 렌더링합니다. `미리보기 포함`을 켜면 현재 링·펼친 영상·출력 미리보기 크기의 렌더 패스도 한 프레임에 포함합니다. 준비 1초 뒤 5초간 측정하며, 독립 타깃 3세트로 최대 3프레임을 동시에 처리합니다. 평균 FPS는 완료 프레임 수 / 실제 경과 시간으로 계산하고 GPU 중앙값·95% 시간은 별도로 표시합니다. 단일 GPU 시간의 역수를 실측 FPS로 제시하지 않습니다. 결과는 렌더 처리량이며 창 합성·HDMI/LED 주사율·영상 디코딩·Ableton·OSC의 전체 처리 성능을 뜻하지 않습니다. 다른 앱의 GPU 사용도 결과에 영향을 줍니다. 측정 중에는 미리보기를 고정하며, 완료·취소·창 닫기 후 정상 재생을 재개합니다. 외부 출력 중이거나 원본 재생 모드에서는 측정을 시작할 수 없습니다.

메인 화면 하단은 영상 출력 상태, OSC 수신 상태·UDP 포트, 제어 송신 상태, 최근 신호의 방향·주소·값을 한 줄로 표시합니다. 영상 출력 중에는 빨간 표시와 함께 대상 모니터·창/전체화면 상태를 표시하고, 상단에는 OSC 매핑·출력 설정·출력 시작/중지 버튼을 모읍니다. 씬별·글로벌 OSC 주소의 수신을 표시하고, 송신은 실제 로컬 OSC 전송 결과를 표시합니다. 하단은 상태 표시 전용이며, 설정은 상단 **OSC 매핑** 버튼에서 엽니다. 최근 신호는 수신·송신 중 가장 최근 항목이며, 재실행하면 초기화됩니다.

OSC 수신은 앱 실행 시 저장한 포트로 자동 시작합니다. 별도 전체 수신·송신 스위치는 없습니다. 각 파라미터의 OSC 주소·송신 여부는 전체 맵에서 항목을 누르거나 파라미터 옆 연결 버튼에서 설정합니다. 해당 항목의 송신 체크를 켜면 바로 전송하고, 체크를 끄면 그 항목만 중단합니다. 별도 이름 입력과 출력 초기화·삭제 버튼은 없습니다. 항목별 송신을 끄면 설정을 보존한 채 중단합니다. 송신 성공은 이 Mac의 전송 결과이며, Live/OSC 수신 확인이나 대상 노브의 실제 값은 아닙니다.

파라미터나 이벤트 옆 연결 버튼에서 OSC 주소를 설정합니다. 앱에는 레이싱 속도·관람객 수 같은 센서 목록이 없으며, 데이터의 의미와 정규화는 송신 쪽에서 결정합니다. 입력은 실수 0.0–1.0이며 범위를 벗어난 유한 값은 제한하고 정수·문자·NaN은 적용하지 않습니다.

## 씬별 조절 항목

메인 화면의 파라미터 목록을 씬 정의에서 직접 만듭니다. 고정된 속도·밝기·에너지 세 칸은 제거했으며, 씬마다 다른 이름과 개수의 조절값을 한두 줄에 모두 표시합니다. 각 항목 옆 연결 버튼에서 입력·출력을 매핑하고, 이름에 마우스를 올리면 설명을 확인할 수 있습니다. 스크롤은 필요하지 않습니다.

영상 파라미터의 슬라이더·현재 값과 OSC 수신 값은 모두 **0.0–1.0**입니다. 실제 셰이더에 전달할 때 각 파라미터의 내부 범위로 변환합니다. 포트 번호와 이벤트 시간(초)은 영상 값과 구분합니다.

`초기값 복원` 버튼(0.5.1)은 현재 씬의 전용 파라미터, 공통 연출값과 재생 속도를 기본값으로 되돌리고 재생 위치를 처음으로 돌립니다. 다른 씬, OSC 입출력 주소, 설치물의 링 방향은 유지합니다. 이후 수신한 OSC 값은 계속 적용됩니다. 원본 재생 모드에서는 원본 조절값만 복원합니다.

| 씬 | 개수 | 메인 화면 파라미터 |
|---|---:|---|
| Chroma Flow | 5 | 주름 밀도, 유체 뒤틀림, 반사선 두께, 반사광 강도, 표면 흐름 |
| Solar Bands | 4 | 밴드 길이, 밴드 밀도, 밴드 명암, 색 띠 간격 |
| Aurora Ribbon | 5 | 리본 폭, 미세 입자 밀도, 테두리 발광, 입자 반짝임, 양옆의 금빛 |
| Electric Corona | 6 | 코로나 길이, 필라멘트 밀도, 필라멘트 휘어짐, 방전 강도, 필라멘트 두께, 안쪽 광륜 |
| Cyan Halo | 3 | 밝은 구간 길이, 헤일로 폭, 회전 가속 |
| Spectral Fragments | 7 | 바 길이, 바 두께, 바 밀도, 바 발광, 생성·소멸 속도, 흐름 변동, 색 띠 비중 |
| Golden Drift | 5 | 금빛 머리 길이, 입자 밀도, 입자 크기, 머리 발광, 입자 반짝임 |
| Pulse Orbit | 23 | 방향 · 힘, 중력, 관성, 중력 위치, 펄스 길이, 펄스 수, 선 두께 · 색상 섹션: 안쪽/가운데/바깥쪽 색상 · 리듬 섹션: 리듬 강도, 리듬 속도, 잔광, 가운데 역회전 · 궤도 섹션: 군집 변화, 궤도별 속도, 바깥쪽 역회전 · 상호작용 섹션: 근접 범위, 연결 강도, 교차 발광, 파동 지속 |

**Pulse Orbit**는 검은 바탕에 세 궤도의 긴 호와 짧은 펄스를 실시간 생성합니다. 기본색은 안쪽 레드, 가운데 화이트, 바깥쪽 레드입니다. 메인 파라미터 영역의 `색상` 섹션에서 각 궤도를 레드/화이트로 선택합니다. OSC 입력은 0.5 미만이면 레드, 0.5 이상이면 화이트이며 중간색은 만들지 않습니다. 색 조절은 메인 화면의 높이를 늘리지 않습니다. 기본 구성은 궤도당 긴 호 두 개와 짧은 펄스 두 개이며, 마지막 펄스는 밀도에 따라 서서히 켜집니다. 각 펄스가 다른 시점에 가속·감속하면서 서로 따라잡거나 벌어집니다. 밝은 선두 뒤로 남는 꼬리는 속도에 따라 늘어나고 사라지며, 점선으로 끊지 않고 연속된 호의 굵기가 변화합니다. 가속할 때 굵어지고 감속·소멸할 때 얇아지며, 꼬리는 끝으로 갈수록 가늘어집니다. 메인 `리듬` 섹션의 강도·속도·잔광으로 변화를 조절하며, 가운데·바깥쪽 역회전을 각각 선택할 수 있습니다. 리듬 강도와 군집 변화가 모두 0이면 추가 가감속이 사라집니다. 펄스 길이·수·선 두께의 기본값은 0.62 / 0.86 / 0.55입니다. 텍스처·블룸은 사용하지 않습니다. `방향 · 힘` 0은 반시계, 0.5는 회전하는 힘 없음, 1은 시계 방향입니다. `관성`이 높으면 감속한 뒤 반전합니다. `중력`은 지정한 각도로 끌리는 연출용 힘이며, 회전하는 힘보다 강하면 빛이 모입니다. `중력 위치`는 0/1이 12시, 0.25가 3시입니다(출력 방향 보정 전). 전체 시간 속도는 공통 조절에서 바꿉니다.

첨부된 `proximare-ring-sim.html`의 근접·교차 구조를 Pulse Orbit에 융합했습니다. 메인 파라미터 영역에 **기본 움직임 / 리듬 / 궤도 / 상호작용 / 색상 / 출력 신호** 메뉴를 항상 표시합니다. 선택한 섹션의 조절값을 13pt 글씨와 넓은 슬라이더로 보여주고, 조절 영역 높이를 고정해 프리뷰 공간을 유지합니다. 별도 팝업 없이 섹션을 전환하며, 직접 실행하는 트리거 이벤트는 맨 아래에 항상 표시합니다. 군집 변화는 점마다 다른 주기의 가감속을 더하고, 안쪽·가운데·바깥쪽 속도는 각각 0–3배(표시값 0–1)입니다. 안팎 펄스가 가까워질수록 흰 연결선이 강해지며, 가운데 펄스도 이웃의 근접에 반응합니다. 실제 각도가 교차하면 흰 섬광과 붉은 파동이 생깁니다. 파동은 LED 띠 안에서 안쪽→바깥쪽으로 움직입니다. 참조의 방·스피커 도식과 WebAudio는 출력하지 않으며 소리는 기존 Live 제어 경로를 사용합니다. 연결 강도와 교차 발광을 0으로 두면 궤도 라인만 남습니다.

색상과 움직임·상호작용을 포함한 23개 파라미터 모두 0–1 OSC 입력과 OSC 출력에 개별 연결할 수 있습니다. 색상은 저장·복원되며 `초기값 복원`으로 기본 팔레트로 돌아갑니다. 새 씬 트리거는 `/orbit/scene/09_pulse_orbit`이며 기존 설정에서 업그레이드해도 추가됩니다. 0.5 이상을 받을 때마다 시뮬레이션을 처음부터 재생합니다. 재생·일시정지, 초기값 복원, 설정 저장과 LED 5행 출력도 기존 씬과 동일합니다. 이 씬은 상태를 유지하는 네이티브 구현이므로 독립 ISF 파일은 제공하지 않습니다.

Pulse Orbit의 메인 **시뮬레이션 출력 신호** 섹션에는 영상 조절값과 별도로 실제 시뮬레이션 출력 4개가 있습니다. 각 연결 버튼에서 OSC 메시지 주소를 설정합니다. OSC 출력 IP·포트는 상단 **OSC 매핑** 화면의 공통 설정을 사용합니다. 기본은 127.0.0.1 / UDP 9001이며 기본 출력은 Float 0–1입니다.

| 출력 신호 | 기본 OSC 주소 | 전송 시점 |
|---|---|---|
| 교차 발생 | `/orbit/09_pulse_orbit/events/crossing` | 교차마다 `1.0` 한 번 |
| 교차 위치 | `/orbit/09_pulse_orbit/events/angle` | 교차 시 논리 링 위치 0–1 |
| 교차 강도 | `/orbit/09_pulse_orbit/events/strength` | 교차 시 두 방출원의 강도 0–1 |
| 현재 근접도 | `/orbit/09_pulse_orbit/events/proximity` | 가장 강한 연결의 근접도, 연속 값 |

교차 위치는 설치 방향 보정 전 좌표이며 0/1=12시, 0.25=3시입니다. 같은 목적지의 위치·강도·트리거는 한 immediate OSC bundle에 순서대로 들어갑니다. 교차 발생은 연속 값 중복 제거와 2초 하트비트에서 제외됩니다. 같은 `1.0`도 교차 횟수만큼 보내며, 일시정지 중에는 새 이벤트가 없고 송신 재개 시 지난 이벤트를 재전송하지 않습니다. 교차 강도는 방출원의 자체 강도이며 화면 밝기·파동 강도 노브와 별개입니다. Live에서 OSC를 받으려면 OSC bundle을 처리하는 Max for Live 장치 등을 사용하고.

입력은 개별 파라미터의 OSC 주소에 Float 0.0–1.0으로 들어옵니다. 스위치는 0.5를 기준으로 전환하고, 씬/재시작 트리거는 0.5 이상인 **모든 패킷**을 처리합니다. 출력 신호 4개는 읽기 전용이며 센서 입력에 연결하지 않습니다. 매핑과 메시지 주소는 씬별로 저장하고, OSC 목적지 IP·포트는 모든 씬이 공유합니다. **OSC 매핑**에 표시되며 최근 송신은 하단 상태 표시줄에서도 확인할 수 있습니다.

검증: `OrbitApp/Tests/PulseOSCChecks.swift`는 격리된 설정과 localhost UDP로 23개 입력→모델→출력, 스위치 경계, 저장 복원, 실제 교차 bundle, 일시정지/송신 재개, 반복 씬 트리거를 확인합니다. `ControlOutputChecks.swift`는 실제 UDP 수신기로 Float 전송·반복 이벤트·송신 테스트·미변환된 이전 MIDI 경로 차단을 확인합니다.

속도·밝기·색상·점등 범위는 **공통 조절**, 설치 방향은 **출력 설정**에서 조절합니다. Spectral의 **색 띠 비중**은 직선 바를 유지하면서 바탕의 색 띠만 드러내거나 지웁니다. 바 길이·두께·생성/소멸 속도도 각각 독립적입니다.

기존 값과 센서·OSC 연결은 유지합니다. 이전 MIDI 출력은 OSC로 변환하며 0–127 범위를 0.0–1.0으로 정규화합니다. 0.3.0에서 연결한 세부 항목이 새 메인 목록에 없으면 **공통 조절 → 기존 연결**에 표시합니다. 이 항목들의 이전 값과 실제 제어도 계속 적용되며, OSC 주소를 바꾸지 않습니다. 원본 재생은 별도의 재생·질감 조절을 유지합니다.

씬별 정의의 원본은 `OrbitShaders/tools/scene_parameters.py`입니다. 생성된 `config/scenes.json`의 `parameters`가 메인 화면과 ISF 노출 항목이며, `compatibilityParameters`는 기존 값과 매핑을 보존하기 위한 항목입니다. GPU 슬롯과 매핑 범위는 각각의 정의를 따릅니다. 하단에는 실행 버전이 표시됩니다.

## 파라미터 입력·출력 매핑

메인 화면 및 **공통 조절**의 각 파라미터 이름 옆 **연결 아이콘**을 누릅니다. 입력과 출력은 서로 독립적으로 켜며, 한 씬에서 여러 파라미터가 동시에 동작합니다. 설정은 씬·영상 소스(실시간 생성/원본 재생)·파라미터별로 저장합니다. 기존 씬당 하나의 매핑도 해당 파라미터로 자동 이전합니다.

- **입력:** 기본 OSC 주소를 사용하거나 사용자 주소로 바꿉니다. 연속값은 0.0–1.0으로 즉시 적용되고 수동 슬라이더도 사용할 수 있습니다. 센서 등록·선택, 별도 입력 범위·보간 설정은 없습니다. 이벤트의 반응 강도·시간은 이벤트 옆 연결 버튼에서 설정합니다.
- **출력:** 센서 또는 수동 조작으로 결정된 실제 영상 값을 OSC Float 하나로 변환합니다. 각 파라미터에 OSC 메시지 주소, 송신 범위를 지정합니다. OSC 대상 호스트·포트는 모든 파라미터에 공통 적용됩니다. 같은 씬에서 출력 주소가 중복되면 충돌 표시와 함께 해당 출력을 중단합니다.
- **제어 출력:** 개별 항목의 송신 체크만 사용합니다. 재실행하면 저장한 체크 상태를 그대로 적용합니다. 이벤트 출력은 해당 이벤트가 새로 발생할 때만 전송하고 이전 이벤트를 다시 보내지 않습니다. 제어 처리는 렌더링과 분리된 30 Hz 타이머를 사용하며, 연속 출력의 동일 값은 묶어 보내고 2초 간격으로 다시 전송합니다. 테스트 씬에서는 제어 자동 송신을 하지 않습니다.

Pulse Orbit의 **라인 추가** 버튼은 반지름이 다른 새 궤도 라인을 하나씩 더합니다. 기본 **3 → 4 → … → 10 → 3** 순환이며, 연결 버튼의 이벤트 입력 설정에서 최대 개수를 **4–10개**로 바꿀 수 있습니다. 현재/최대 개수는 버튼 옆에 표시됩니다. 추가한 라인은 다음 이벤트까지 유지되고, `펄스 수` 슬라이더와 연속 출력은 그대로입니다. 최대 개수 설정과 OSC 매핑은 저장하고, 실행 중 추가된 개수는 처음부터 재생·씬 재선택·앱 재실행 시 3개로 돌아갑니다. 이벤트 출력 주소의 기본값은 `/orbit/09_pulse_orbit/events/addLine`입니다. 이벤트 수신 모드에서 Float ≥ 0.5 메시지마다 한 라인씩 추가하며, 상한 초과도 한 번의 이벤트로 출력합니다.

**연속값과 트리거 이벤트는 별도 타입과 ID입니다.** 연속값 슬라이더에는 실행 버튼이 없습니다. 메인 화면의 별도 **트리거 이벤트** 줄에서 영상별 동작을 직접 실행합니다. 각 이벤트 옆 연결 버튼에서 독립된 입력·출력 주소를 설정합니다.

| 씬 | 독립 트리거 이벤트 |
| --- | --- |
| Chroma Flow | 반사광 섬광 · 유체 충격 · 표면 압축 |
| Solar Bands | 밴드 확장 · 밴드 점화 · 밴드 수축 |
| Aurora Ribbon | 오로라 점화 · 리본 수축 · 입자 폭발 |
| Electric Corona | 방전 · 광륜 섬광 · 필라멘트 수축 |
| Cyan Halo | 광선 확장 · 가속 충격 · 소멸 파동 |
| Spectral Fragments | 바 폭발 · 스펙트럼 점화 · 순간 소멸 |
| Golden Drift | 입자 폭발 · 금빛 섬광 · 꼬리 소멸 |
| Pulse Orbit | 궤도 펄스 · 중력 충격 · 궤도 반전 · 라인 추가 |

- **연속값:** OSC Float 0.0–1.0을 영상 값에 바로 적용합니다. 연속 출력은 이 값만 전달합니다.
- **트리거 입력:** 로그인 같은 이벤트는 0.5 이상인 메시지마다 실행합니다. 같은 1.0이 반복돼도 각각 처리합니다. 별도 **영상 값으로 자동 실행**에서 영상의 연속값을 선택하면 임계값 이상으로 올라갈 때 한 번 실행하며, 임계값 − 재무장 간격 이하로 내려가야 다시 실행합니다.
- **영상 반응:** 이벤트마다 반응 강도와 시작·유지·소멸 시간을 정합니다. 해당 씬의 여러 요소에 일시적인 반응을 적용하고 복귀합니다. 연속값의 저장값·슬라이더 표시·연속 출력은 변경하지 않습니다.
- **트리거 출력:** 각 이벤트에 별도 주소를 지정합니다. 발생할 때 OSC Float `1.0` 한 번을 보냅니다. 대기 중이나 소멸 중에는 큐나 하트비트를 보내지 않습니다. 기본 주소는 `/orbit/<scene>/events/<event>`입니다.

예: `/park/login 1.0` → Electric Corona의 **방전** 이벤트 → 영상에 한 번 방전 + `/orbit/04_electric_corona/events/discharge 1.0` → Live 클립 실행. 연속 파라미터인 **방전 강도**는 원래 값과 입력 매핑을 유지합니다. 한 번만 소리를 재생하려면 Live 클립의 Loop를 끄세요. OSC는 bundle을 해석하는 Max for Live 수신 장치 등이 필요합니다.

매핑·반응 설정은 씬별로 저장하며, 진행 중인 이벤트와 실행 횟수는 저장하지 않습니다. 이전 방식의 파라미터 이벤트 매핑은 `trigger.parameter.<id>`라는 별도 트리거로 옮겨 OSC 주소·출력 연결을 보존합니다. 글로벌 씬 선택·재생 동작도 ‘수신마다’ 또는 ‘임계값 통과’를 선택합니다.

상단 **OSC 매핑** 화면 안에서 OSC 수신 UDP 포트와 공통 OSC 출력 IP·포트를 입력하고 **적용**합니다. 127.0.0.1은 같은 Mac이며, 다른 컴퓨터로 보내려면 그 컴퓨터의 IP를 입력합니다. 연속값, 트리거, 교차 이벤트, 테스트 송신이 모두 같은 목적지를 사용하고, 각 파라미터의 OSC 주소와 송신 범위는 개별 설정을 유지합니다. 설정은 재실행 후에도 복원됩니다. 수신 중 포트를 바꾸면 수신기를 다시 열고, 출력 목적지만 바꾸면 현재 영상과 이벤트 상태를 유지하며 새 목적지로 전환합니다. 이전 개별 목적지는 현재 씬 우선으로 활성 OSC 목적지를 승계하며, 공통 설정을 저장한 이후에는 개별 IP·포트를 사용하지 않습니다.

OSC 전체 맵은 **왼쪽 입력 / 오른쪽 출력**을 같은 폭으로 나눕니다. 전체·글로벌·영상별 범위, 신호 종류, 영상 소스, 검색을 양쪽에 함께 적용하고 각 목록은 따로 스크롤합니다. 양쪽 항목에 씬·파라미터 이름을 표시합니다. 글로벌은 입력 목록만 있으며 출력 쪽에는 전용 안내를 한 번 표시합니다. 출력 전용 시뮬레이션 신호는 오른쪽에만 표시합니다.

주소·복사·수신/송신 체크·연속값/트리거 출력 방식·송신 최소/최대·송신 테스트를 목록에서 직접 조작합니다. 주소는 Enter 또는 포커스를 옮길 때 저장해 입력 중 정렬이 바뀌지 않도록 합니다. 다른 씬을 편집해도 현재 재생 씬을 바꾸지 않으며, 송신 테스트는 현재 씬에서만 가능합니다. 이벤트 반응 시간 등 세부 설정은 메인 파라미터 옆 연결 버튼에서 조절합니다. 입력에는 수신값과 수신 표시, 출력에는 실제 전송 완료 값과 송신 표시·실패를 각각 표시합니다. 송신값은 목적지와 씬·영상 소스별로 구분하며 상대 장치의 수신 확인을 뜻하지 않습니다. 연속 입력을 트리거 출력으로 바꾼 항목은 연속값·트리거 필터 양쪽에서 찾을 수 있습니다.

글로벌 트리거는 **0.5 이상인 메시지를 받을 때마다 한 번 실행**합니다. 같은 0.8을 세 번 보내면 세 번 실행하며, 중간에 0을 보낼 필요가 없습니다. 씬 선택은 같은 씬이어도 처음부터 재생합니다. 기본 주소는 `/orbit/scene/<scene-id>`, `/orbit/scene/next`, `/orbit/scene/previous`, `/orbit/restart`, `/orbit/play`, `/orbit/pause`이며 전체 맵에서 주소 수정·비활성화할 수 있습니다. 글로벌 목록은 실제 씬 선택·다음/이전·재생·일시정지·처음부터 동작에 연결되어 있으며, 임의 추가·삭제·동작 변경 버튼은 없습니다. 이전 사용자 주소와 별칭은 유지하고 빠진 기본 동작은 자동으로 복원합니다. 다음·이전은 콘텐츠 씬만 순환하고 테스트 패턴은 특정 씬 주소로 선택합니다.

OSC 전체 맵 왼쪽 **이 Mac · 수신 IP**에 현재 네트워크 IP를 표시합니다. 송신 프로그램에서는 연결된 네트워크의 IP와 수신 UDP 포트를 사용합니다. 여러 IP가 있으면 메뉴에서 인터페이스별 주소를 확인하고 복사할 수 있습니다. 연결 상태는 3초마다 갱신하며, 네트워크가 없으면 그 상태를 표시합니다.

영상별 제어에도 기본 수신 주소가 있습니다. 앱 실행 후 별도 센서를 만들거나 수신을 시작하는 조작 없이 바로 보낼 수 있습니다.

| 용도 | 기본 주소 예 | 값 |
| --- | --- | --- |
| Pulse Orbit 씬 선택 | `/orbit/scene/09_pulse_orbit` | Float ≥ 0.5 수신마다 처음부터 |
| 라인 추가 | `/orbit/scene/09_pulse_orbit/events/addLine` | Float ≥ 0.5 수신마다 1회 |
| 궤도 펄스 | `/orbit/scene/09_pulse_orbit/events/orbitPulse` | Float ≥ 0.5 수신마다 1회 |
| 방향·힘 | `/orbit/scene/09_pulse_orbit/parameters/directionDrive` | Float 0.0–1.0 |
| 원본 재생 밝기 | `/orbit/scene/01_chroma_flow/original/parameters/brightness` | Float 0.0–1.0 |

전체 맵 왼쪽에서 수신 주소 변경·복사·비활성화가 가능합니다. 기본 주소 복원은 메인 파라미터의 매핑 버튼에서 제공합니다. 직접 수신은 해당 씬과 영상 소스가 재생 중일 때만 적용하며, 다른 씬으로 전환하지 않습니다. 이벤트는 매번 실행하고, 연속값은 정규화된 영상 값을 즉시 설정합니다. 주소와 활성 상태는 저장하며 이전 설정 파일에도 기본 주소를 제공합니다. 출력 전용 시뮬레이션 신호에는 수신 주소가 없습니다.

파라미터와 트리거의 연결 버튼 옆 파란 수신등은 유효한 외부 OSC 메시지를 받으면 켜지고 약 1초 뒤 사라집니다. 같은 값의 반복 수신도 표시하며, 트리거는 0.5 미만 메시지도 수신 자체를 표시합니다. 수동 조작·내부 시뮬레이션·송신 테스트는 수신등을 켜지 않습니다. Pulse Orbit의 섹션 메뉴와 OSC 전체 맵에도 같은 수신 표시가 있고, 수신등에 마우스를 올리면 최근 값·시간·수신 횟수를 확인할 수 있습니다. 수신 이력은 재실행하거나 씬을 바꾸면 초기화합니다.

연속값 파라미터의 **출력 → 출력 방식**에서 **연속값 / 트리거**를 선택합니다. 연속값은 현재 값을 기존 송신 최소·최대 범위로 보내고, 트리거는 유효한 OSC 입력 메시지마다 같은 출력 주소로 Float `1.0`을 한 번 보냅니다. `0.0`이나 같은 값의 반복 입력도 각각 한 번 보냅니다. 입력은 계속 연속값으로 영상에 적용되며, 트리거 출력에 0.5 임계값은 적용하지 않습니다. 직접 슬라이더 값을 변경한 경우도 한 번 송신하고, 값이 유지되는 동안에는 트리거를 반복 송신하지 않습니다. 출력 주소·연속값 송신 범위·선택한 모드는 저장되며 모드만 바꿔도 이벤트가 발생하지 않습니다. **송신 테스트**는 선택한 모드로 한 번 전송합니다.

외부 입력이 없는 Pulse Orbit의 숫자 출력도 두 방식을 선택할 수 있습니다. **현재 근접도**는 시뮬레이션의 샘플 값이 바뀔 때, **교차 위치·강도**는 교차가 발생할 때마다 실제 값 또는 트리거 `1.0`을 보냅니다. 기존 **교차 발생**과 트리거 이벤트 버튼은 계속 `1.0`을 한 번 보내는 전용 이벤트입니다.

이전 센서 연결은 저장된 OSC 주소와 인수를 직접 수신 설정으로 옮깁니다. 이미 수정한 직접 주소가 있으면 그 주소를 우선하며, 센서 목록과 숨은 추가 입력 경로는 제거합니다. 이전 설정 원본은 사용자 설정의 `OrbitSettings.beforeAddressOnly.v1`에 한 번 보관합니다. 기존 센서 범위·보간·수신 중단 시 복귀는 더 이상 적용하지 않으며 송신 쪽에서 정규화한 값을 전달합니다. 같은 씬의 여러 항목이 같은 주소를 받아 함께 반응할 수 있습니다. 글로벌 동작 주소와 충돌하면 오류를 표시하고 해당 직접 수신을 실행하지 않습니다. 제어 출력 주소는 유지합니다.

이벤트 실행은 메인 화면의 **트리거 이벤트** 버튼에서 합니다. 별도 이벤트 설정 패널과 팝업 내 실행 버튼은 제거했습니다. 연결 팝업은 해당 항목의 주소·반응·송신만 설정합니다. 전체 맵에서는 입출력 주소와 기본 송신 설정을 팝업 없이 직접 편집합니다. 출력 시작·중지·전체화면은 메인 상단에서 조작하며, 출력 설정에는 모니터·해상도·프리뷰·링 방향 설정만 둡니다. LED 테스트는 메인 Calibration 씬에서 선택합니다.

## 공연·설치 설정 복원

선택 씬, 모든 파라미터/매핑, OSC 포트, FPS, 출력 해상도, 프리뷰 정책, 출력 모니터를 자동 저장합니다. 모니터는 재연결 시 바뀔 수 있는 번호 대신 디스플레이 UUID로 기억합니다. 없으면 현재 화면으로 대체하며 원래 모니터 정보는 보존합니다. 종료 시 보류 중인 설정도 저장합니다.

**출력 설정 → 앱 실행 시 이전 영상 출력 상태 복원**은 기본으로 켜져 있습니다. 별도 출력 창과 전체화면 상태를 복원하며, 끄면 영상 출력은 메인 버튼으로 시작합니다. OSC 수신과 체크된 항목의 송신은 이 옵션과 무관하게 자동 준비됩니다. 수신 포트 연결이 실패하면 OSC 매핑의 같은 **적용 / 다시 연결** 버튼으로 포트를 고쳐 적용하거나 재시도할 수 있습니다. 송신 체크된 항목이 없는 상태는 업데이트 설치를 막지 않습니다.

메인 운영 창을 닫거나 앱을 종료하면 별도 전체화면 출력, 렌더링, OSC 수신과 제어 송신을 함께 종료합니다. 종료 직전의 운영 상태를 먼저 저장하므로 다음 실행의 복원 설정은 유지됩니다. 출력 창만 닫으면 출력만 중지하고 운영 창은 계속 사용할 수 있습니다.

**운영 화면 프리뷰**는 항상 켜기 / 출력 전체화면에서 끄기 / 끄기 중 선택합니다. 끄면 링·펼친 영상·출력 미리보기 Metal 뷰를 제거하고 원본 비교 플레이어도 정지합니다. 실제 LED 출력과 센서·Live 제어는 유지합니다. 출력 전체화면에서 자동으로 끈 프리뷰는 출력 중지 또는 창 모드로 돌아오면 다시 표시됩니다. 별도 출력 창은 모든 씬/원본 재생에서 LED 5행 배치로 고정되며 운영 앱 창을 전체화면으로 만드는 동작과 구분됩니다.

### Ableton Live 연결

1. **OSC 매핑**에서 공통 출력 IP·UDP 포트를 설정합니다. 기본값 `127.0.0.1:9001`은 같은 Mac의 수신 프로그램입니다.
2. 파라미터의 **출력** 탭에서 OSC 주소와 송신 최소·최대를 설정하고 **이 파라미터 송신**을 켭니다. 기본 범위는 **0.0 → 1.0**이며 소수점을 항상 표시합니다.
3. **송신 테스트**는 선택한 연속값 또는 이벤트를 한 번만 보냅니다. 파라미터 송신 여부와 전체 자동 송신 설정은 바꾸지 않습니다.
4. **제어 자동 송신**을 켜면 활성 파라미터의 연속값을 보내고, 트리거는 이벤트 발생마다 Float `1.0`을 한 번 보냅니다.
5. Live에서는 Max for Live 등 OSC 수신 장치에서 주소별로 클립·장치에 연결합니다. 오디오 재생·스피커 채널 라우팅은 Live가 담당합니다.

MIDI 출력과 가상 MIDI 포트는 제거했습니다. 이전 설정의 MIDI 항목은 주소와 켜짐 여부를 보존하여 OSC로 변환하며, 최소·최대는 127로 나눠 0.0–1.0으로 바꿉니다. 기존 OSC 범위는 그대로 유지합니다. **UDP 송신 성공은 상대 앱 수신 확인이 아닙니다.**

## LED 출력

논리 링은 **15444 × 300**입니다. 기준 캔버스는 3840 × 2160이며 왼쪽 위에 3564 × 300 네 줄과 1188 × 300 한 줄로 배치하고 나머지는 검정으로 출력합니다. 다른 해상도를 선택하면 이 배치 전체를 16:9 비율로 스케일링합니다.

**출력 설정 → 디스플레이 · 크기**에서 모니터와 해상도를 선택합니다. 기본값인 **현재 화면 / 화면에 맞춤**은 외부 모니터 없이 사용 가능합니다. **출력 시작**을 누르면 크기 조절 가능한 별도 창이 열리며, 앱에서 다른 기능을 조작해도 출력 창이 위에 유지됩니다. 창의 **전체화면** 버튼, 녹색 창 버튼 또는 **⌘⇧F**로 해당 모니터의 전체화면을 사용하고, Esc로 창 모드로 돌아옵니다. 창 모드로 돌아온 뒤에도 위에 유지됩니다. **출력 중지** 또는 **⌘.**으로 출력을 종료합니다.

자동 해상도는 창·모니터의 Retina 배율까지 반영합니다. HD·FHD·QHD·4K 또는 직접 입력은 지정한 렌더 해상도를 유지하면서 화면에 맞춰 표시합니다. 직접 입력은 가로 320–7680 px 범위, 16 px 단위이며 세로는 자동 계산합니다. 16:9가 아닌 화면은 검정 여백으로 비율을 유지합니다. 출력 창을 닫으면 출력과 빨간 표시도 꺼집니다.

LED의 1:1 픽셀 테스트는 **4K** 선택, **3840 × 2160 디스플레이의 전체화면**에서 진행합니다. 실제 LED의 방향·구간 순서는 테스트 패턴으로 확인합니다.

**Calibration → 테스트 → 구간 1–5 + 안팎 띠**는 다섯 가지 구간색과 중앙의 큰 번호를 유지합니다. 제공된 배치 도면의 숫자 방향을 기준으로, 펼친 LED 영상의 **각 줄 위쪽은 바깥쪽(파랑), 아래쪽은 안쪽(빨강)**입니다(안팎 반전 끔 기준). 링 프리뷰에서도 파랑은 바깥 둘레, 빨강은 안쪽 둘레에 표시되며 숫자의 머리쪽이 바깥을 향합니다. 각 띠는 300픽셀 높이 기준 24픽셀(8%)이며 출력 해상도에 맞춰 비례 조절됩니다. IN·OUT 글자는 표시하지 않습니다. **안쪽만**, **바깥쪽만**에서도 켜진 쪽의 구간색·번호·방향 띠를 유지하며 반대쪽은 검정으로 끕니다. 기존 테스트 패턴 번호는 유지합니다.

## 파일 구성

- `OrbitApp/`: SwiftUI 운영 화면, Metal 렌더러, OSC 수신, 출력 창, 원본 비교 플레이어
- `OrbitShaders/src/`: GLSL 공통 수식과 씬 소스
- `OrbitShaders/metal/`, `OrbitShaders/isf/`: 생성된 Metal / ISF 셰이더
- `OrbitShaders/config/`: 씬·파라미터·매핑 정의
- `OrbitShaders/tools/`: 생성·렌더·검증 도구
- `OrbitTextures/`: 비교용 추출 텍스처와 출처 메타데이터
- `KakaoTalk_Video_2026-11-10-09-37-08.mp4`: 앱의 원본 비교용 영상

세부 좌표와 셰이더 구조는 [셰이더 문서](OrbitShaders/README.md)를 참고하세요. `OrbitHybrid_*` 파일은 이전 실험의 보관 코드이며 현재 앱에서 실행하지 않습니다.
