# Orbit shader pack

제공된 `KakaoTalk_Video_2026-11-10-09-37-08.mp4`의 다섯 표현과 추가 스틸컷을 참고해 만든 실시간 절차적 셰이더입니다. 수식 생성 모드는 원본 영상 파일이나 인터넷 연결 없이 생성합니다. 앱에는 별도로 추출 텍스처 모드도 있으며 아래 설명을 참고하세요. 영상의 실제 제작 소스를 추출한 결과가 아닌, 시각적 특징을 재구성한 버전입니다. 2026-11-10 수정에서는 원본의 미세 입자·불규칙한 밴드·방사형 빛줄기·명암 분포를 다시 작업했습니다. 원본 제작 알고리즘의 복원이나 동일 프레임 재현을 보장하는 버전은 아닙니다.

## 생성 방식과 운영 화면 (2026-11-10 수정)

기본 아트 출력은 **실시간 생성**입니다. 형상·색·질감·시간 변화를 씬별 셰이더 코드로 계산하며 이미지나 영상 텍스처를 입력하지 않습니다. **원본 재생**은 추출 리소스를 재생하는 별도 비교용 소스입니다. 이전의 PNG+패턴 혼합 모드는 앱 실행 경로와 UI에서 제거했습니다. 기존 저장 설정은 한 번 실시간 생성으로 전환하고, 센서 주소·매핑과 개별 연출 값은 유지합니다.

`07_spectral_fragments`는 매끈한 색 띠와 직선 파편을 분리해서 생성합니다. 파편의 원주 좌표에는 방사 좌표를 섞지 않으므로 선이 휘거나 주름지지 않습니다. 대리석 모양 노이즈, 굴절 주름과 두꺼운 발광 테두리는 사용하지 않습니다. 색 띠는 원주를 따라 흐르고, 세 파편 층은 서로 다른 속도로 이동하며 독립적으로 생성·소멸합니다. 시간과 센서는 파편별 수명·밝기·점유 범위, 색 띠의 위치를 바꿉니다. 매끈한 형태를 유지하면서 기본 속도에서도 이동이 보이도록 구성했습니다. 스틸컷에는 속도 정보가 없으므로 시간 변화는 새로 구성한 것입니다. 실제 GPU 렌더링 12초 영상은 `previews/07_spectral_fragments.mp4`, 참조 비교와 동작 검증은 `review/spectral-code/`에 있습니다.

상단 시간 표시는 실제 셰이더의 누적 시간입니다. 재생/일시정지·속도·처음부터와 함께 동작합니다.

메인 화면에는 재생/정지, 8개 씬, 링·펼친 영상·4K 배치 미리보기, 속도·밝기·에너지, 센서 상태만 남겼습니다. **씬 연출 / 센서 입력 / 센서 매핑 / 출력 설정**은 고정 크기 팝업으로 열립니다. 긴 설정은 탭으로, 센서 목록은 6개씩 페이지로 나누어 메인과 팝업 모두 스크롤 없이 사용합니다.

### 추출 리소스

- 영상 참조 01–05: 원본 링을 프레임마다 2048×96의 펼친 띠로 추출한 H.264, 24fps. 1.00×에서 원본 구간의 질감·움직임·가속을 그대로 재생합니다.
- 스틸 참조 07·08: 정지 이미지의 링을 추출한 PNG. 재생 시 회전·흐름 변형을 줄 수 있으며 원본의 시간 변화가 들어 있는 영상은 아닙니다.
- 이전 혼합 모드의 보관 리소스 01–05: 원본 12·37·56·94·115초에서 각각 추출한 PNG. 07·08은 위의 스틸 PNG를 공유합니다. `seedFile`과 `seedSourceSeconds`가 출처입니다.
- 파일은 `../OrbitTextures/textures/`, 추출 좌표·구간·프레임 수는 `../OrbitTextures/manifest.json`에 있습니다.
- `src/texture_body.metal` → `metal/OrbitTexture.metal`이 원본 텍스처를 샘플링하고 대비·왜곡·발광·색·소등 마스크를 실시간 적용합니다. 중립 기본값은 입력 질감을 보존합니다.
- 원본 입력은 1280×720이며 링의 방사 방향 실제 세부량은 약 32픽셀입니다. 2048×96 텍스처와 15444×300 논리 출력으로 확대해도 원본에 없는 세부가 생기지는 않습니다.
- 이 해상도 제한은 원본 재생에 해당합니다. 기본 실시간 생성은 출력 픽셀마다 수식으로 계산하므로 추출 이미지의 해상도에 의존하지 않습니다.
- 영상은 장면 구간을 반복합니다. 시작/끝이 일치하도록 만들어진 원본이 아니므로 반복 경계의 내용 전환은 남습니다.

실제 앱과 같은 `OrbitTextureSource`/AVAssetReader/CVMetalTexture 경로로 7개 씬의 디코딩, Metal 렌더, 4K 패킹, 검정 여백을 검증했습니다. 영상 씬은 마지막 프레임 후 처음으로 돌아오기와 정지 프레임 유지도 확인했습니다. 결과는 `../OrbitTextures/review/validation.json`, 원본 비교는 `../OrbitTextures/review/original-vs-texture.jpg`입니다. 실제 HDMI/LED 현장 출력 검증은 별도입니다.

이전 혼합 모드의 검증 기록: 7개 씬은 PNG 로딩부터 실제 Metal 출력까지 `tools/HybridProbe.swift`로 검증했습니다. 논리 띠와 4K 패킹의 차이는 채널당 최대 1/255, 여백은 검정이며 밝기 0과 흐름 변형도 확인했습니다. 시간차 프레임에서 최적 전체 회전을 제거한 뒤에도 국소 변화가 남는지 검사했습니다. 결과는 `../OrbitTextures/review/hybrid/validation.json`과 `non-rigid-motion.json`입니다.

추출 재생성: `python3 tools/extract_textures.py` 다음 `python3 tools/build_shaders.py`. 앱 빌드 전에 `xcodegen generate --spec ../OrbitApp/project.yml`을 실행합니다. PNG/H.264 리소스는 앱 번들에 포함됩니다.

## 파일 구성

- `metal/`: macOS 네이티브 앱용 Metal 생성 셰이더. 씬별 fragment / compute 진입점과 공통 fullscreen vertex.
- `isf/`: 동일한 효과 계산식을 사용하는 ISF 2.0 `.fs` 생성기. Millumin 등의 ISF 호스트에서 사용하기 위한 버전.
- `src/`: 두 형식의 공통 원본. 효과 수정 후 빌드 스크립트를 실행합니다.
- `config/scenes.json`: 씬 목록, 기본값, 파라미터 범위, 진입점, uniform 구조, 출력 좌표 정의.
- `config/osc-mappings.example.json`: 씬별 OSC 주소 및 값 변환의 예시. 실제 데이터 항목과 범위에 맞춰 변경합니다.
- `previews/`: 실제 M3 Max Metal 렌더링으로 생성한 장면별 PNG·MP4, 비교 이미지, 검증·성능 결과.
- `previews/test-patterns/`: 정확한 3840×2160 테스트 패턴 PNG 원본.
- `previews/LED-test-patterns-3840x2160-60fps.mp4`: 현장용 테스트 영상. 무음, 총 30.5초.
- `tools/`: 재생성, macOS GPU 렌더링, 검증, 테스트 영상 출력 도구.

## 좌표와 출력

논리 링은 **15444×300**입니다. 정규화 좌표 `u`는 12시에서 시계 방향으로 0-1, `v`는 안쪽에서 바깥쪽으로 0-1입니다. 화면 좌표 원점은 왼쪽 위입니다.

| viewMode | 용도 |
|---|---|
| 0 | 펼친 띠. 정확한 원본 크기는 15444×300. 작은 해상도는 비율을 압축한 미리보기로 사용 가능 |
| 1 | 원형 미리보기. `ringWidth`는 미리보기 링의 외반지름 대비 폭이며 실제 출력 픽셀 수를 바꾸지 않음 |
| 2 | 3840×2160 기준 전송 배치. 출력 해상도에 맞춰 전체 배치를 16:9로 스케일링 |

| 구간 | 시작 X | 크기 | 4K 화면의 위치 |
|---|---:|---|---|
| 1 | 0 | 3564×300 | 0,0 |
| 2 | 3564 | 3564×300 | 0,300 |
| 3 | 7128 | 3564×300 | 0,600 |
| 4 | 10692 | 3564×300 | 0,900 |
| 5 | 14256 | 1188×300 | 0,1200 |

5번째 줄의 오른쪽, 전체 콘텐츠 오른쪽 및 아래쪽은 불투명 검정입니다. UI의 빨간 출력 테두리는 셰이더에 포함하지 않습니다. `angleOffset`, `flipU`, `flipV`는 공통 매핑 설정입니다. 앱은 자동·HD·FHD·QHD·4K·직접 입력 해상도와 창/전체화면 출력을 지원합니다. 자동 모드는 출력 창의 실제 픽셀 크기를 사용하며 16:9 외부 여백은 검정입니다. 1:1 픽셀 검사는 4K를 선택하고 3840×2160 화면에서 전체화면으로 진행합니다. 방향·안팎 확인은 실제 LED에서 테스트 패턴으로 진행해야 합니다.

## 씬별 파라미터

`tools/scene_parameters.py`에서 씬별 파라미터의 의미, 범위, 기본값, GPU 슬롯, 기존 항목의 이전 관계를 정의합니다. 생성된 `config/scenes.json`의 각 씬 `parameters`를 사용하세요. 예를 들어 Spectral Fragments의 `barLength`, `barWidth`, `lifetimeRate`는 바 길이·두께·생성/소멸 주기를 독립적으로 제어합니다. 앱과 ISF는 같은 항목을 노출합니다. GPU 슬롯 `density/turbulence/energy`와 `shape0…3`은 내부 저장 위치이며, 사용자에게 보이는 이름은 각 씬의 정의를 따릅니다.

기존 혼합 모드 파일은 보관용으로 일반 빌드에서 재생성하지 않습니다.

## Metal 앱 연결

`metal/` 파일들을 라이브러리에 컴파일하고 `config/scenes.json`의 `fragmentFunction`을 사용합니다. vertex는 `orbit_fullscreen_vertex`, 삼각형 정점 수는 3입니다. 실제 픽셀 기준 drawable 크기와 viewport를 사용합니다.

**컴파일 시 `MTLCompileOptions.fastMathEnabled = false`를 사용하십시오.** 정밀한 극좌표 변환과 노이즈 계산을 위해 이 설정으로 실제 검증했습니다. 빠른 수학 모드에서는 일부 각도에 미세한 선이 발생할 수 있습니다.

fragment의 uniform은 `buffer(0)`에 96바이트로 전달합니다. compute의 경우 출력 RGBA8 버퍼가 `buffer(0)`, uniform이 `buffer(1)`입니다. 24개 float32를 다음 순서대로 저장합니다. JSON의 `uniformBuffer.fields`가 기준입니다.

```text
outputWidth, outputHeight, viewMode, phaseTime,
density, turbulence, energy, hueShift,
brightness, seed, angleOffset, flipU,
flipV, ringWidth, testPattern, markerWidth,
coverage, gapSoftness, gapMotion, fragmentation,
shape0, shape1, shape2, shape3
```

보관된 혼합 모드의 진입점 `orbit_hybrid_<scene ID>_fragment`는 기존 80바이트를 유지하고 **추가 buffer(1)에 16바이트** `generation, sharpness, evolution, detail`을 전달합니다. compute에서는 추가 버퍼가 `buffer(2)`입니다. 참조 PNG는 `texture(0)`입니다. 구현은 `src/hybrid_body.metal`, 생성 결과는 `metal/OrbitHybrid_*.metal`이며 이전 네이티브 Metal 전용 구현입니다. 현재 앱은 이 진입점을 사용하지 않습니다. 현재 실시간 생성과 ISF는 위의 96바이트 uniform과 씬별 코드 생성 진입점을 사용합니다.

색상은 display-referred SDR RGB입니다. `RGBA8Unorm` 출력 기준이며, 이미 표시용으로 설계된 값을 sRGB render target에서 다시 인코딩하지 않습니다. 앱의 전체 색관리 파이프라인에 선형 중간 합성을 도입한다면 입력/출력 변환을 명시적으로 적용해야 합니다.

`outputWidth/Height`는 양수, 모든 값은 유한한 수여야 합니다. 센서 범위 검증과 clamp는 CPU 매핑 계층에서 처리합니다. 셰이더는 네트워크 데이터나 OSC 주소를 읽지 않습니다.

## 빛의 등장과 소멸

`coverage`는 빛이 남는 원주 범위(0=전체 소등, 1=전체 범위), `gapSoftness`는 사라지는 경계의 부드러움, `gapMotion`은 빈 구간의 이동, `fragmentation`은 켜진 구간 내부의 조각화입니다. 마스크는 색과 윤곽선까지 모두 곱하므로 꺼진 구간에 링 테두리가 남지 않습니다. 이 효과는 공간별로 변화하며 전체 화면 점멸이 아닙니다. 테스트 패턴에는 적용하지 않습니다. 앱에서 범위·이동·조각화를 OSC 센서에 매핑할 수 있습니다.

영상 참조 씬 01–05는 기본 `coverage=1`입니다. 원본에 없는 일괄적인 검정 틈을 제거했고, 유체·청록색의 어두운 부분은 각 셰이더 내부 명암으로 생성합니다. 스틸컷 기반 07의 조각 소멸은 각 조각의 수식에서, 08의 어두운 꼬리는 머리 밝기와 범위에서 생성합니다. 범위를 줄이면 추가 소등 연출이 적용됩니다.

네이티브/ISF/GPU 검증 도구를 함께 업데이트한 96바이트 uniform 버전입니다. 예전 64/80바이트 호스트와 혼용하지 마세요.

## 시간과 센서 매핑

`phaseTime`은 누적된 연출 시간입니다. 속도를 바꿀 때 `현재 시각 × 새 속도`를 매 프레임 계산하면 장면이 튑니다. 네이티브 앱은 실제 프레임 간격으로 다음처럼 시간을 누적해야 합니다.

```text
phaseTime += deltaSeconds × smoothedSpeed
```

예시 매핑은 수신 30초 간격, stale 90초를 가정합니다.

- `/park/racing/speed` 0-100 → clock.speed 0.25-1.5, 8초 보간.
- `/park/visitors` 0-500 → density 0.2-0.85, 12초 보간.
- `/park/racing/speed` 0-100 → energy 0.35-0.85, 8초 보간.

네이티브 실행 앱은 씬별 매핑을 저장하며, 씬 선택 시 시계를 재시작합니다. 씬 간 크로스페이드는 아직 구현하지 않았습니다. 테스트 씬에서는 센서 매핑을 기본 해제합니다. brightness는 별도의 운영용 마스터 밝기로 유지하는 것을 권장합니다.

인접한 `../OrbitApp/Orbit.xcodeproj`에 네이티브 실행 앱, OSC 수신·보간, 디스플레이 선택 UI가 있습니다. Ableton 브리지는 아직 구현하지 않았습니다. 앱의 “원본 비교”는 원본 전체 프레임 MP4를 비교 모니터에 표시합니다. 원본 플레이어는 셰이더의 누적 시간·속도를 따라가며 드리프트를 보정합니다. 비교를 켜거나 “처음부터”를 누르면 함께 시작합니다. 원본 플레이어만 참조 구간 길이로 반복하고 생성기의 시계는 계속 진행합니다. “연출 기본값 복원”은 해당 씬의 속도·시각 기본값을 복원합니다. 서로 다른 알고리즘이므로 동일 프레임 복제를 의미하지 않습니다.

2026-11-10 속도 보정: 영상 참조 01–05의 기본 속도 배율은 1.00입니다. 청록색은 원본 106–126초의 밝기 중심을 분석해 초반 약 4.2초/회전의 반시계 흐름과 후반 가속을 해석식으로 피팅했습니다. 비교 모드를 끈 상시 재생에서는 가속 후 6초간 부드럽게 감속해 속도 주기를 반복합니다. 수식 생성 모드의 형상·색·미세 무늬는 수식으로 만들며 원본 샘플 텍스처/프레임 시퀀스를 사용하지 않습니다. 스틸컷만 있는 07·08은 원본 동작 속도를 측정할 수 없으므로 구성한 움직임을 사용합니다.

`review/motion-comparison.json`은 수정 전후의 프레임 변화량과 밝기 중심 이동 측정입니다. 원본과 생성기의 파형이 같다는 증거가 아니라 시간감각을 비교하는 지표입니다. `review/cyan-motion-comparison.mp4`는 원본 106–126초와 수식 생성 결과를 같은 경과 시간으로 나란히 보여줍니다.

## Millumin / ISF 사용

`.fs`는 기존 영상을 처리하는 effect가 아니라 영상을 생성하는 **source**입니다. Millumin 공식 문서의 경로는 `~/Library/Millumin/ISF-source/`입니다. 필요한 `.fs`를 넣고 Millumin을 다시 실행해 셰이더 라이브러리에서 선택합니다. 자동 설치는 하지 않았습니다.

- `View = Ring preview`: 참고 영상과 비교.
- `View = Packed 4K`: 생성 해상도를 3840×2160으로 지정하고 1:1 출력.
- `View = Unwrapped`: 펼친 논리 링.
- 단독 재생은 `TIME × speed`를 사용합니다. OSC로 speed를 연속 변경할 때는 호스트에서 누적 시간을 계산해 `Use continuous host clock = true`, `clockSeconds`에 전달하십시오.
- `clockSeconds`가 부족하면 호스트의 입력 범위를 늘리십시오. 파라미터 정의의 86400은 UI 범위이며 셰이더 내부에서 시간을 강제로 반복하지 않습니다.

ISF JSON과 GLSL 컴파일을 확인했습니다. **Millumin 앱에서 직접 불러오는 검증은 아직 수행하지 않았습니다.** 호스트의 버전·색관리·해상도 설정에 따라 별도 확인이 필요합니다.

공식 참고: https://help.millumin.com/docs/tutorials/create-images-and-effects-with-shaders/

## 테스트 패턴

| 번호 | 내용 |
|---|---|
| 0 | 1-5 구간 번호, 진행 화살표 |
| 1 | 100×50 픽셀 간격의 1픽셀 격자 |
| 2 | 안쪽 빨강 / 바깥쪽 파랑 |
| 3 | RGB 채널 |
| 4 | 16단계 회색 램프 |
| 5 | 흰색 |
| 6 | 검정 |
| 7 | 이동 마커: 12.5초에 한 바퀴 |
| 8 | 구간 접합부 |
| 9 | 1픽셀 체커보드 |

테스트 MP4는 0,1,2,3,4,5,6,8,9번을 각 2초씩 보여준 후 마커가 한 바퀴 돕니다. 호환성이 높은 H.264/YUV 4:2:0 형식으로 인코딩되므로 색 경계·1픽셀 정밀 검사에는 네이티브 테스트 씬 또는 무손실 PNG를 사용하십시오. 파일 재생 시 화면 맞춤 확대와 플레이어 컨트롤을 해제하고 1:1로 출력해야 합니다.

## 재생성과 검증

Python 도구는 개발·검증용입니다. 최종 앱은 Python 없이 Metal 셰이더를 실행할 수 있습니다. 도구 의존성은 `pyobjc-framework-Cocoa`, `numpy`, `Pillow`, `ffmpeg`입니다.

```sh
python3 tools/build_shaders.py
python3 tools/validate.py
python3 tools/render_metal.py --benchmark --video
python3 tools/export_test_video.py
```

검증은 실제 M3 Max에서 수행했습니다. 결과는 `previews/validation.json`, 성능은 `previews/benchmark.json`에 기록합니다. 성능 수치는 GPU compute 작업만 측정하며 디스플레이 출력·영상 디코딩·미리보기 합성·Ableton 동시 실행을 포함하지 않습니다. 실제 HDMI와 LED 현장 시험은 별도입니다.
